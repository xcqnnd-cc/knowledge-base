# 🚀 前端转 AI 应用开发：全栈方向 (Node/Python) 的 10 周实战项目清单与计划表

目标不是学一堆枯燥的 AI 理论概念，而是让你在 **10 周内**，做出几类真正像样的 AI 商业级应用。

---

## 🎯 一、先定目标：你要学成什么样？

不是泛泛的“懂一点 AI”，而是要达到以下四个实战能力：

1.  💬 能做一个 **流式聊天产品**
2.  📊 能做一个 **结构化输出的业务页面**
3.  📚 能做一个 **带知识库检索的问答系统 (RAG)**
4.  🛠️ 能做一个 **带工具调用的 AI 工作流 (Agent)**

做到这一步，你去面试“AI 应用开发 / AI 产品前端 / 全栈 AI 工程”就已经有实实在在的作品可讲了。

---

## 🛠️ 二、技术栈别乱，直接这样定

不要被层出不穷的新框架迷了眼，认准这套高效的实战技术栈：

### 1. 前端 (Frontend)
*   **核心框架**：Vue 3 + Vite + TypeScript
*   **状态与路由**：Pinia + Vue Router
*   **UI 组件库**：Element Plus 或 Naive UI
*   **Markdown 渲染**：`markdown-it`
*   **代码高亮**：`highlight.js` 或 `shiki`

### 2. 服务端 (Backend/BFF) —— Node 与 Python 双线任选
作为前端转型，你需要一个服务端层来处理密钥和复杂的 AI 逻辑。你可以根据自己的熟悉度选择：
*   🟢 **Node.js 路线（平滑过渡）**：TypeScript + **Hono** (轻量且写 AI API 非常顺手) 或 Express / NestJS。
*   🔵 **Python 路线（AI 生态更优）**：Python 3 + **FastAPI** (轻量异步) 或 Flask。如果你未来想深入 LangChain / LlamaIndex 生态，推荐走这条线。

### 3. AI 接入层
*   **基础 SDK**：OpenAI 官方 SDK (Node / Python 均支持良好)
*   **进阶能力**：
    *   Structured Outputs (结构化输出)
    *   Tool Calling / Function Calling (工具调用)
    *   File Search / RAG (文件检索)
    *   Evals (评测)

### 4. 存储与工程辅助
*   **数据库**：SQLite / PostgreSQL (前期够用就行)，Node 可配 Prisma，Python 可配 SQLAlchemy。
*   **数据校验**：**Zod** (Node) / **Pydantic** (Python) —— 这是做 Schema 校验、实现 AI 结构化输出的神器。
*   **接口调试**：Postman / Bruno

---

## 🗺️ 三、项目顺序别跳，按这个清单做

### 🟢 项目 1：AI 聊天助手 (基础入门)
这是入门项目，但要做得像真正的产品，而不是一个简陋的 textarea 加按钮。

*   **你需要实现**：多轮对话、流式输出 (SSE)、Markdown & 代码块渲染、中断生成、重新生成、会话列表持久化。
*   **核心锻炼点**：基础模型调用、流式响应处理、消息状态管理、前后端接口联动。
*   **灵魂拷问**：SSE 和普通请求有什么区别？前端怎么做流式拼接？失败重试怎么设计？

### 🟡 项目 2：结构化输出助手 (业务结合)
这个项目非常重要，它会把你从“做聊天页前端”拉到“做真正的业务 AI 前端”。

*   **应用场景**：简历解析助手、合同提取助手、会议纪要结构化。
*   **你需要实现**：上传文本 -> AI 返回标准 JSON -> 前端将 JSON 渲染成表单或卡片 -> 用户可修改字段并导出。
*   **核心锻炼点**：Structured Outputs、JSON Schema (Zod/Pydantic)、Schema 驱动 UI 设计、“AI 输出 -> 业务组件” 的闭环链路。

### 🟠 项目 3：知识库问答系统 (企业级核心)
这是企业内部最刚需的 AI 应用原型。

*   **应用场景**：公司文档问答、产品手册问答、法务条款问答。
*   **你需要实现**：文件上传与管理、知识问答、**引用来源展示**、命中的片段高亮、没命中时的兜底提示。
*   **核心锻炼点**：RAG (检索增强生成)、文档状态管理、引用链路设计、证据展示 UI。

### 🔴 项目 4：带工具调用的 AI 工作台 (Agent 雏形)
这是决定你有没有“AI 应用工程意识”的关键项目，让 AI 不仅能回答问题，还能**执行动作**。

*   **应用场景**：天气查询、订单查询、工单查询的统一工作台。
*   **你需要实现**：左侧聊天区 + 右侧工具执行状态区；实时展示 tool calling 中、成功、失败的状态；将工具结果回填给模型继续回答。
*   **核心锻炼点**：Function Calling、Tool Schema 设计、前端状态机思维、AI 工作流可视化编排。

## 📅 四、10 周实战突击周计划表

| 阶段 | 周次 | 核心目标 | 关键产出 |
| :--- | :--- | :--- | :--- |
| **打底** | **第 1 周** | 跑通最小调用链路 | Vue + Hono/FastAPI 基础项目搭建，跑通一问一答 API。 |
| **项目 1** | **第 2 周** | 实现流式聊天体验 | 支持 SSE 逐字输出、Markdown 渲染、中断与重新生成。 |
| | **第 3 周** | 完善多会话系统 | 实现会话列表、历史记录保存、本地/数据库持久化。 |
| **项目 2** | **第 4 周** | 结构化输出业务页 | 掌握 Schema 定义，实现“文本输入 -> 渲染成结构化表单”页面。 |
| **项目 3** | **第 5 周** | 文件上传与解析 | 实现文件列表管理、文本提取与状态追踪。 |
| | **第 6 周** | RAG 知识库问答 | 接入检索能力，实现带有“引用来源和高亮”的问答系统。 |
| **项目 4** | **第 7 周** | 工具调用 (Tool Calling) | 定义工具 Schema，实现 2-3 个 Mock 工具供 AI 调用。 |
| | **第 8 周** | Agent 工作流 UI | 设计步骤流 UI，展示 AI 思考过程与工具执行的各阶段状态。 |
| **收尾** | **第 9 周** | 评测与回归测试 | 建立测试集，比较 Prompt 策略，记录失败 Case。 |
| | **第 10 周** | 简历与作品集整理 | 录制演示视频，总结技术难点，形成可投递的在线作品集。 |

> **💡 建议**：不要一上来就去啃复杂的微调、Transformer 原理或者大模型底层算法。你现在最缺的不是这些，而是 **全栈 AI 应用的落地工程能力**。

## 🧱 五、前端做 AI 应用最该补的 6 个短板

1.  **服务端开发能力**：必须补！你要学会建 API 路由、管密钥、控权限、控超时、控日志，无论用 Node 还是 Python，否则你永远只是个“调接口的前端”。
2.  **前端状态机意识**：AI 页面状态极其复杂（正在生成、已中断、工具执行中、等待确认等），必须学会按状态机来设计 UI。
3.  **Schema 意识**：牢记一句话：**“能结构化输出，就绝对别让 AI 自由输出文本”**。学会在服务端用 Zod 或 Pydantic 约束 AI。
4.  **错误兜底意识**：模型超时、工具调用失败、无检索结果、输出格式不合法……这些异常流的 UX 设计是考验 AI 产品体验的关键。
5.  **可视化表达能力**：这是前端的最大优势。把 AI 的输出变成卡片流、表单流、步骤流、证据链，而不是死板的一段长文本。
6.  **评测意识**：没有评测和回归测试集的 AI 功能，根本不敢上生产环境。

## 📝 六、做完这 4 个项目后，简历该怎么写？

**❌ 减分写法**：
> 学习了 OpenAI，了解了大模型，做了一个聊天机器人。

**✅ 加分写法 (结果导向)**：
> *   **项目 1（AI 智能助手）**：基于 Vue 3 + 服务端 (Node/Python) 实现全栈流式聊天系统，攻克 SSE 实时流输出、Markdown 复杂渲染、会话状态机管理及请求中断重试等核心工程难点。
> *   **项目 2（业务结构化引擎）**：深度应用 AI 结构化输出能力 (Structured Outputs)，打通“非结构化文本 -> 标准 JSON -> Schema 驱动表单渲染”的业务链路，支持复杂字段的可视化编辑与校验。
> *   **项目 3（企业级知识问答）**：落地 RAG (检索增强生成) 架构，实现大文件切片上传、向量检索与答案生成闭环。首创“答案 + 证据引用”双层展示 UI，显著提升 AI 问答在业务场景下的可信度。
> *   **项目 4（AI Agent 工作台）**：基于 Function Calling 封装多类业务查询工具，实现 AI 工具自动调度、执行状态实时追踪与结果回填，打造具备高可观测性的 Agent 工作流交互体验。

---

## 💡 七、最后的实在建议

不要走**“学一堆 AI 概念，再想办法做项目”**的弯路。
最适合前端向全栈 AI 工程师转型的路线是：**“先动手做这 4 个项目，在项目里反推自己缺什么知识”**。

这条路线最大化利用了你原有的优势（UI、状态管理、组件化），同时逼迫你补齐了最关键的短板（服务端能力、AI 工程链路、Schema 设计）。

**行动起来，用 10 周时间，从“前端执行者”蜕变为“全栈 AI 应用工程师”！**
